# ElectronicLoad

Программа для электронной нагрузки (разряд аккумуляторов с построением графика) и две прошивки для платы **WeAct Studio BlackPill STM32F401**:

* **battery_emu** — эмулятор: нагрузка вместе с подключённым аккумулятором, полный цикл разряда до безопасного напряжения, без всякой силовой части;
* **electronic_load** — настоящая нагрузка постоянного тока до **60 Вт**: ОУ + MOSFET + шунт, ADS1115, ACS712, кулер процессора ПК. Схема и сборка описаны в [docs/hardware.md](docs/hardware.md).

Обе прошивки работают с одним и тем же WPF-приложением, весь процесс в реальном времени выводится на график.

```
┌──────────────────────────┐   USB CDC (виртуальный COM-порт)   ┌──────────────────────────────┐
│  WpfApp (Windows, .NET 8)│ ◄────────────────────────────────► │  Firmware (BlackPill F401)   │
│  график U / I / P / T    │        протокол PX-100             │  модель аккумулятора +       │
│  таблица, CSV, PNG       │                                    │  нагрузка постоянного тока   │
└──────────────────────────┘                                    └──────────────────────────────┘
```

Обе прошивки говорят по **протоколу электронной нагрузки PX-100** (rev. 2.70), который приложение уже поддерживает. Поэтому одно и то же приложение без изменений работает с настоящей PX-100 (через её USB-UART), с эмулятором и с самодельной нагрузкой. Общий код (USB, протокол, тактирование) лежит в `Firmware/src`. Протокол обращается к нагрузке через интерфейс `device.h`, который реализуют `battery_emu.c` (эмулятор) и `load/load.c` (настоящая нагрузка).

## Прошивка (Firmware)

### Что она делает

* Плата определяется в системе как виртуальный COM-порт (USB CDC ACM, VID/PID `0483:5740`). В Windows 10/11 драйвер `usbser.sys` ставится сам.
* Команды протокола PX-100 обрабатываются так же, как у настоящей нагрузки: включение/выключение, ток, напряжение отсечки, таймер, сброс счётчиков, чтение U, I, мА·ч, мВт·ч, температуры и времени.
* Внутри работает модель **аккумулятора** и **нагрузки постоянного тока**:
  * напряжение холостого хода по таблице OCV(SoC) для Li-ion (NMC, 4.2 В) или LiFePO4;
  * внутреннее сопротивление R0 даёт мгновенную просадку при включении нагрузки;
  * RC-цепочка поляризации (Rp, τ) даёт плавную просадку под нагрузкой и плавное восстановление напряжения после отключения;
  * подсчёт ёмкости (мА·ч), энергии (мВт·ч) и времени теста;
  * нагрев радиатора нагрузки от рассеиваемой мощности (с тепловой инерцией);
  * небольшой шум измерений U и I, чтобы было похоже на настоящее АЦП.
* Нагрузка **сама отключается**, если:
  1. напряжение опустилось до **напряжения отсечки** из приложения;
  2. напряжение опустилось до **безопасного минимума** `BAT_SAFE_MV` (2.5 В на Li-ion элемент, 2.0 В на LiFePO4). Этот предел срабатывает даже если в приложении отсечка задана ниже или равна 0;
  3. истёк **таймер**;
  4. радиатор перегрелся (`LOAD_OVERTEMP_C`).
* **Ускорение времени.** По умолчанию модель идёт в 60 раз быстрее реального времени (`EMU_TIME_SCALE`). Разряд элемента 2500 мА·ч током 1 А занимает около 2.5 минут вместо 2.5 часов. Время теста, таймер, мА·ч и мВт·ч считаются в модельном времени, а ось X графика в приложении идёт в реальных секундах.

### Индикация и кнопка

| Светодиод PC13 | Состояние |
|---|---|
| горит | нагрузка включена, идёт разряд |
| мигает 1 Гц | нагрузка отключилась сама (отсечка, безопасный минимум, таймер, перегрев) |
| короткая вспышка раз в 2 с | ожидание |
| быстро мигает | не запустился кварц 25 МГц (USB может не работать) |

**KEY (PA0)** вставляет новый, полностью заряженный аккумулятор: нагрузка выключается, счётчики обнуляются.

Кроме того, если предыдущий разряд закончился по отсечке, то при следующем **Start** из приложения эмулятор сам ставит новый заряженный элемент и обнуляет счётчики. Так можно запускать цикл за циклом, не трогая плату.

### Сборка

Нужны `arm-none-eabi-gcc` (GNU Arm Embedded Toolchain) и `make`.

```sh
cd Firmware
make                # build/battery_emu.elf, .bin, .hex
```

* Linux: `sudo apt install gcc-arm-none-eabi make`
* Windows: [Arm GNU Toolchain](https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads) + `make` (MSYS2, Git for Windows SDK или `choco install make`), либо WSL.

Параметры можно поменять в `src/config.h` или прямо из командной строки:

```sh
make clean && make CDEFS="-DEMU_TIME_SCALE=120 -DBAT_CAPACITY_MAH=3400"
```

### Сборка в IAR Embedded Workbench for Arm

1. Открыть `Firmware/EWARM/ElectronicLoad.eww` (*File → Open Workspace*). В нём два проекта: **electronic_load** (настоящая нагрузка) и **battery_emu** (эмулятор). Активный проект выбирается на вкладке проекта или правой кнопкой → *Set as Active*.
2. Выбрать конфигурацию **Debug** (оптимизация Low) или **Release** (оптимизация High) и нажать *Project → Make* (F7). *Project → Batch Build → All* собирает всё сразу.
3. Результат: `Firmware/EWARM/<конфигурация>/Exe/<проект>.out` (ELF с отладочной информацией) и `<проект>.hex`. Hex можно прошить через DFU или STM32CubeProgrammer (см. ниже).
4. Прошивка и отладка из IAR: подключить ST-LINK к SWD (SWDIO, SWCLK, GND, 3V3) и нажать *Project → Download and Debug* (Ctrl+D). В файлах `.ewd` уже выбраны драйвер ST-LINK и flash loader для STM32F401xC.

Что настроено в проекте:

| Параметр | Значение |
|---|---|
| Кристалл | ST STM32F401CC, Cortex-M4, FPU VFPv4 single precision |
| Define | `STM32F401xC`; у electronic_load ещё `APP_LOAD` |
| Include | `..\src`, `..\Drivers\CMSIS\Include`, `..\Drivers\CMSIS\Device\ST\STM32F4xx\Include`; у electronic_load ещё `..\load` |
| CMSIS | из репозитория (встроенный CMSIS IAR выключен, чтобы не было двух копий `core_cm4.h`) |
| Стартовый файл | `startup_stm32f401xc.s` от ST. Вызывает `SystemInit()` (включает FPU), затем `__iar_program_start` → `main()` |
| Линкер | `stm32f401xc_flash.icf`: flash `0x08000000`–`0x0803FFFF`, RAM `0x20000000`–`0x2000FFFF`, CSTACK 4 КБ |
| Выход | `electronic_load.out/.hex`, `battery_emu.out/.hex` |

В проекты IAR входят те же исходники, что и в Makefile, кроме `src/startup.c`: это стартовый файл только для GCC. Параметры меняются в `src/config.h` (эмулятор) и `load/load_config.h` (нагрузка) или в *Project → Options → C/C++ Compiler → Preprocessor → Defined symbols* (например `EMU_TIME_SCALE=120` или `CURRENT_SENSOR=CURRENT_SENSOR_SHUNT`).

Проект сделан на основе шаблона STM32CubeF4 для EWARM (формат EWARM 7.x). IAR 8.x и 9.x откроют его и при первом сохранении предложат обновить формат, это нормально.

### Прошивка платы

**Через USB (встроенный DFU-загрузчик), без программатора:**

1. Зажать **BOOT0**, нажать и отпустить **NRST**, отпустить **BOOT0**. Плата появится как *STM32 BOOTLOADER* (`0483:df11`).
2. Прошить:
   * `make dfu` (нужен [dfu-util](https://dfu-util.sourceforge.net/); в Windows драйвер WinUSB ставится через Zadig), или
   * [STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html): интерфейс USB, файл `build/battery_emu.hex` или `.bin` по адресу `0x08000000`, *Start Programming*.
3. Нажать NRST, и плата появится как новый COM-порт.

> Если F401 не входит в DFU с первого раза (известная особенность BlackPill), повторите комбинацию кнопок или держите BOOT0 чуть дольше.

**Через ST-Link** (SWDIO, SWCLK, GND, 3V3): `make flash` (нужен `st-flash` из stlink-tools) или STM32CubeProgrammer в режиме SWD.

### Основные параметры (`src/config.h`)

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `EMU_TIME_SCALE` | 60 | во сколько раз модель быстрее реального времени (1 = реальное время) |
| `EMU_CHEMISTRY` | `EMU_CHEM_LIION` | химия элемента: `EMU_CHEM_LIION` или `EMU_CHEM_LIFEPO4` |
| `BAT_CELLS_SERIES` | 1 | количество элементов последовательно |
| `BAT_CAPACITY_MAH` | 2500 | ёмкость |
| `BAT_R0_MOHM` | 60 | внутреннее сопротивление элемента |
| `BAT_RP_MOHM`, `BAT_TAU_S` | 40, 40 | поляризация: сопротивление и постоянная времени |
| `BAT_SAFE_MV` | 2500 / 2000 | безопасный минимум на элемент (Li-ion / LiFePO4) |
| `LOAD_MAX_CURRENT_MA` | 10000 | максимальный ток нагрузки |
| `LOAD_AMBIENT_C`, `LOAD_RTH_C_PER_W_X10`, `LOAD_THERMAL_TAU_S` | 25, 15, 180 | модель радиатора: окружающая температура, 1.5 °C/Вт, инерция |
| `LOAD_OVERTEMP_C` | 80 | защита от перегрева |
| `EMU_NOISE_MV`, `EMU_NOISE_MA` | 2, 3 | амплитуда шума измерений |
| `BOARD_HSE_HZ` | 25000000 | кварц BlackPill |

### Проверка модели без платы

Та же модель и тот же протокол собираются для ПК (Linux, macOS, WSL):

```sh
make sim
make curve                                                    # полный разряд 1 А до 3.0 В в CSV
build/sim/battery_emu_sim --curve --current 3 --cutoff 3.0    # другой ток и отсечка
build/sim/battery_emu_sim --scale 600                         # протокол PX-100 на stdin/stdout
```

Пример (`make curve`, 2500 мА·ч, 1 А, отсечка 3.0 В): 4.14 В в начале, плато около 3.7 В, отключение на 3.0 В после 2470 мА·ч и 9.2 Вт·ч. Модельное время 2 ч 28 мин, реальное около 2.5 мин.

## Настоящая нагрузка 60 Вт (Firmware/load)

Схема, детали, тепловой расчёт, калибровка и порядок первого включения описаны в **[docs/hardware.md](docs/hardware.md)**. Коротко:

* **Силовая часть:** ШИМ (PA6, 20.5 кГц, 12 бит) → RC-фильтр → делитель → два канала «ОУ + MOSFET IRFP250N + шунт 0.1 Ом» → ток до 10 А. Сама стабилизация тока аналоговая. Прошивка задаёт опору, ограничивает мощность 60 Вт (ток снижается до P/U), плавно поднимает ток и медленной подстройкой убирает смещение ОУ и разброс резисторов.
* **Измерения:**
  - **ADS1115**, 16 бит: напряжение АКБ измеряется дифференциально по Кельвину, ток — через ACS712-20A (ратиометрически, с автоматическим нулём) или через шунт.
  - **Встроенный АЦП** читает температуру кристалла. Почему для U и I выбран ADS1115, объяснено в [docs/hardware.md](docs/hardware.md#какой-ацп-использовать-ads1115-или-встроенный).
* **Охлаждение:** 4-pin кулер процессора ПК, ШИМ 25 кГц (PA8). Скорость зависит от мощности, после остановки кулер ещё 60 с работает. Обороты (PA1) контролируются: если кулер встал, нагрузка выключается.
* **Защиты:**
  - отсечка и таймер, как у PX-100;
  - перенапряжение, перегрузка по току и мощности, перегрев, отказ кулера, отказ АЦП, ток при выключенной нагрузке;
  - сторожевой таймер;
  - аппаратный прижим опоры (PB12): при сбросе МК нагрузка гарантированно выключена.
* **Светодиод:** горит — нагрузка включена; 1 Гц — остановка по отсечке или таймеру; 5 Гц — авария; вспышка раз в 2 с — ожидание. **KEY** немедленно останавливает нагрузку.

Сборка: `make load` (GCC, результат в `build/electronic_load.*`) или проект **electronic_load** в `Firmware/EWARM/ElectronicLoad.eww`. Прошивка платы: `make dfu-load` / `make flash-load` или STM32CubeProgrammer, как для эмулятора. Номиналы схемы, пределы и калибровочные коэффициенты задаются в `Firmware/load/load_config.h`.

## WPF-приложение (WpfApp)

Требования: Windows 10/11, [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) (или Visual Studio 2022 с workload *.NET desktop development*).

```sh
cd WpfApp
dotnet build -c Release
dotnet run
```

или открыть `WpfApp/ElectronicLoad.sln` в Visual Studio.

### Полный цикл разряда с эмулятором

1. Подключить прошитую BlackPill к USB. В диспетчере устройств появится новый *COM*-порт («Устройство с последовательным интерфейсом USB»).
2. В приложении в группе **Serial port** нажать ⟳, выбрать этот порт и нажать **Connect**. Скорость (9600) для USB CDC ни на что не влияет.
3. В **Load settings** задать ток (например 1 А), **напряжение отсечки** (например 3.0 В для Li-ion) и при необходимости таймер. Нажать **Apply to device**.
4. Нажать **Start**. Появится окно подтверждения с током, отсечкой и таймером. Это защита от случайного нажатия. После **OK** счётчики устройства обнуляются, нагрузка включается, и график начинает строиться: напряжение, ток, мощность и температура радиатора, а на плитках ещё мА·ч и мВт·ч.
5. Когда напряжение дойдёт до отсечки (или до безопасного минимума), эмулятор сам отключит нагрузку. Приложение покажет *«Load switched off by the device…»* и остановит запись.
6. Сохранить результат: **File → Save Graph (CSV)** или **Export Graph as PNG**.
7. Повторный **Start** после окончания теста показывает предупреждение: новый тест начнётся с чистого листа (график, таблица и счётчики устройства очищаются). В окне можно сначала сохранить данные в CSV (**Yes**), начать без сохранения (**No**) или отказаться (**Cancel**). Эмулятор при этом ставит новый, полностью заряженный элемент.

Если тест остановлен вручную кнопкой **Stop**, следующий **Start** спрашивает, что делать: продолжить этот же тест на той же оси времени (**Yes**) или начать новый с чистого листа (**No**, затем то же предупреждение с предложением сохранить данные). **Clear Data** в любой момент очищает график и счётчики, и следующий **Start** снова считается первым запуском.

На графике напряжение и ток идут по левой оси, мощность по правой, температура по отдельной правой оси, чтобы её шкала (25–40 °C) не сжимала кривую разряда.

## Протокол PX-100 (кратко)

Запрос всегда 6 байт: `B1 B2 CMD D1 D2 B6`.

| CMD | Команда | Данные | Ответ |
|---|---|---|---|
| `01` | нагрузка вкл/выкл | D1 = 1 / 0 | `6F` |
| `02` | ток | D1 = целые А, D2 = сотые | `6F` |
| `03` | напряжение отсечки | D1 = целые В, D2 = сотые | `6F` |
| `04` | таймер | D1:D2 = секунды (big-endian), 0 = выкл | `6F` |
| `05` | сброс мА·ч / мВт·ч / времени | – | `6F` |
| `10` | нагрузка включена? | – | `CA CB d1 d2 d3 CE CF` (24 бит, старший байт первым) |
| `11` / `12` | напряжение, мВ / ток, мА | – | то же |
| `13` | время теста | – | d1 = ч, d2 = мин, d3 = с |
| `14` / `15` / `16` | мА·ч / мВт·ч / °C | – | 24 бит |
| `17` / `18` | уставка тока А·100 / отсечки В·100 | – | 24 бит |
| `19` | уставка таймера | – | ч, мин, с |

Источник: [misdoro/Electronic_load_px100](https://github.com/misdoro/Electronic_load_px100). Реализация для ПК находится в `WpfApp/PX100Protocol.cs`, для устройства в `Firmware/src/px100.c`.

`Firmware/Drivers/CMSIS` содержит заголовки CMSIS от Arm (CMSIS 5.9.0) и STMicroelectronics (cmsis_device_f4) под лицензией Apache-2.0. Тексты лицензий лежат рядом с файлами. `Firmware/EWARM/startup_stm32f401xc.s` и `stm32f401xc_flash.icf` взяты из cmsis_device_f4 (Apache-2.0, текст в `Firmware/Drivers/CMSIS/Device/ST/STM32F4xx/LICENSE.md`). Размер стека в `.icf` увеличен до 4 КБ.
